# Архитектура

Правила слоёв и размещения кода. Где что физически лежит и кто кого вызывает — смотри через
Serena; здесь только то, что каждому слою разрешено и запрещено.

## Слои и ответственность

Порядок обработки: route → middleware (`auth:sanctum`) → FormRequest → Controller → Service → Repository

- **Controller** — тонкий. Принятая в проекте форма: взять данные из FormRequest, привести типы,
  вызвать сервис, вернуть `response()->json(...)`; сервисное исключение ловится `catch (\Exception)`
  и превращается в ответ через `$this->error($exception)` из базового `Controller`.
  Запрещено: бизнес-условия, Eloquent-запросы, запись в БД.
- **FormRequest** — только валидация. Бизнес-правил в `rules()` нет. В новых Request создавай `messages()`.
- **Service** — вся бизнес-логика, единственный слой, который решает, что происходит. Текущего
  пользователя сервис берёт сам через `Auth::id()` / `Auth::user()`. Если логика обширная,
  выносим её в Handler внутри директории сервиса (пример — `Chat/Handler/CreateChatHandler`).
- **Util** — `Services/<Домен>/Util/*RulesUtil`: статические проверки-предохранители, бросают
  `HandledException`. Один метод — одно правило.
- **DTO** — `Services/<Домен>/DTO` (+ `Factory`).
- **Repository** — доступ к данным, наследует `AbstractRepository`.
- **Resource** — ресурсы ответа.

## Данные пользователя

- Проверка существования записи (`*RulesUtil::isExists`) принимает `$userId` и ищет запись
  только среди принадлежащих пользователю. Проверка «просто по id» — уязвимость.

## Размещение нового кода

- Новая бизнес-возможность — отдельная самодостаточная папка домена внутри `app/Services/`
  (`Repositories/`, `Util/`, при необходимости `Handler/`, `DTO/`, `Swagger/`).
- Новый репозиторий — в `Services/<Домен>/Repositories/`, наследует `AbstractRepository`,
  модель задаётся через `protected Model $model` в конструкторе.
- Новый контроллер — в `app/Http/Controllers/Api/<Домен>/`, запрос — в `app/Http/Requests/Api/<Домен>/`.
- Маршруты домена — в `app/Providers/Routes/<Домен>/<Домен>RoutesProvider.php` (метод `register()`),
  подключаются в `routes/api.php`; защищённые маршруты — внутри группы `auth:sanctum`.
- Не создавай новую абстракцию, если в проекте уже есть подходящая. Сначала найди аналог через Serena.

## Форма сервиса

- Зависимости — через constructor property promotion, `private readonly`.
- Репозитории и хендлеры инжектируются конкретными классами: интерфейсов репозиториев и
  биндингов в `AppServiceProvider` в проекте нет. Интерфейсы не вводи без моей просьбы.
- Параметры конструктора выравниваются в одну колонку.
- Тип возвращаемого значения объявляется всегда, включая `void`.
- Группированные `use`-импорты.

## Ошибки

- Исключение — `HandledException`.
- Текст ошибки в проекте — обычная строка. Функции `___()` в проекте нет, существующие сообщения
  не переписывай и не переноси в файлы переводов по своей инициативе.
- Код исключения — это HTTP-статус: `Controller::error()` использует его как статус ответа, если он
  в диапазоне 100–511, иначе отвечает 400. Статус в новом коде лучше брать константой
  `Symfony\Component\HttpFoundation\Response::HTTP_*`; в существующем коде стоят числа (404, 401) — не переписывай.

```php
throw_if(
  $isNotActiveEmail, 
  HandledException::class, 
  'Message', 
  Response::HTTP_FORBIDDEN
);
```

## Условия

- называй проверки и переменные так, чтобы нужный случай был положительным: `isRefundRequired()`,
  `isRefundAcquired`, `isEnvironmentAllowed`;
- клади положительный случай в `if` и выполняй работу внутри него;

```php
$isRefundAcquired = $this->claimPayoutRepository->acquireRefund($payout->id);

if ($isRefundAcquired) {
    $this->refundToUtip($payout);
}
```
